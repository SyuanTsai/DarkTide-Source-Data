## Passive values and capacity

The talent installs its same-named buff. The buff has `max_stacks = 1`, `ability_extra_charges = 1`, and `combat_ability_resource_cost_per_use_modifier = 0.33`. It has no event trigger, temporary duration or accumulating proc stacks. Its two effects are applied once; the shared stat aggregator limits effective stacks to one. [Talent and display parameters](https://github.com/Aussiemon/Darktide-Source-Code/blob/7e662fcda16219d775b84af50322be2e9cd9d62e/scripts/settings/ability/archetype_talents/talents/veteran_talents.lua#L606-L644); [Passive buff](https://github.com/Aussiemon/Darktide-Source-Code/blob/7e662fcda16219d775b84af50322be2e9cd9d62e/scripts/settings/buff/archetype_buff_templates/veteran_buff_templates.lua#L358-L366); [Effective stack count](https://github.com/Aussiemon/Darktide-Source-Code/blob/7e662fcda16219d775b84af50322be2e9cd9d62e/scripts/extension_systems/buff/buffs/buff.lua#L404-L410).

Infiltrate inherits the base Veteran ability's charge usage, `ability_extra_charges` stat, **one base charge** and **one resource unit of regeneration per second**. Its clone changes the base per-charge cost to **40 resource units**. `max_ability_charges` adds the extra-charge value to the equipped ability's base capacity, giving **1 + 1 = 2 stored charges** with this modifier alone. This is storage capacity, not a promise of two immediate grants on every initialization or respawn. The current tree places Overwatch under Infiltrate; the stat implementation itself uses the equipped combat ability's configuration. ## Per-charge cost and regeneration

`ability_extra_charges` is a value stat; `combat_ability_resource_cost_per_use_modifier` is an additive-multiplier stat with neutral value 1. Overwatch adds 0.33 to the existing cost multiplier. For base cost `C₀`, flat per-use cost adjustment `f`, and other additive cost deltas `m`, the threshold cost before the extension's rounding is:

```text
C = (C₀ + f) × (1 + m + 0.33)
```

The implementation rounds the cost to hundredths using its configured epsilon. With Overwatch alone, `C₀ = 40`, `f = m = 0`, so `C = 40 × 1.33 = 53.2 resource units`. It is neither `40 × 0.33` nor a reduction to 33% of the old cooldown. [Cost stat types](https://github.com/Aussiemon/Darktide-Source-Code/blob/7e662fcda16219d775b84af50322be2e9cd9d62e/scripts/settings/buff/buff_settings.lua#L731-L742); [Charge stat type](https://github.com/Aussiemon/Darktide-Source-Code/blob/7e662fcda16219d775b84af50322be2e9cd9d62e/scripts/settings/buff/buff_settings.lua#L691-L695); [Additive stat aggregation](https://github.com/Aussiemon/Darktide-Source-Code/blob/7e662fcda16219d775b84af50322be2e9cd9d62e/scripts/extension_systems/buff/buffs/buff.lua#L689-L727); [Per-charge cost and rounding](https://github.com/Aussiemon/Darktide-Source-Code/blob/7e662fcda16219d775b84af50322be2e9cd9d62e/scripts/extension_systems/ability/player_unit_ability_extension.lua#L1437-L1461); [Rounding constants](https://github.com/Aussiemon/Darktide-Source-Code/blob/7e662fcda16219d775b84af50322be2e9cd9d62e/scripts/extension_systems/ability/player_unit_ability_extension.lua#L21-L24).

The actual resource update computes the net rate rather than starting an independent timer for each charge. Define `Rbase` as the ability's allowed base flat/percentage regeneration, `Rflat` as the flat regen stat, `Rmult` as its regen modifier, and `D` as `get_ability_resource_cost_per_second`:

```text
Net rate N = (Rbase + Rflat) × Rmult − D
New pool  = clamp(old pool + N × dt, 0, maximum pool)
Available charges = clamp(floor(pool / C), 0, maximum charges)
```

The pool is quantized for its component representation. The update runs when resource is missing or an ongoing cost must be paid. Pausing or disabling the ability makes its base regeneration zero; separate flat regeneration and ongoing costs still enter the formula. If `N ≤ 0`, a missing charge does not naturally refill under these fixed conditions. The cooldown estimate below assumes constant positive `N`, unchanged cost/capacity, no discrete restoration, no usage during that interval and no pause. [Resource update and charge thresholds](https://github.com/Aussiemon/Darktide-Source-Code/blob/7e662fcda16219d775b84af50322be2e9cd9d62e/scripts/extension_systems/ability/player_unit_ability_extension.lua#L773-L880); [Update requirement and pause state](https://github.com/Aussiemon/Darktide-Source-Code/blob/7e662fcda16219d775b84af50322be2e9cd9d62e/scripts/extension_systems/ability/player_unit_ability_extension.lua#L1192-L1229); [Ongoing resource cost](https://github.com/Aussiemon/Darktide-Source-Code/blob/7e662fcda16219d775b84af50322be2e9cd9d62e/scripts/extension_systems/ability/player_unit_ability_extension.lua#L1382-L1403).

With only Overwatch, `N = 1 resource unit/second`, so one full missing charge takes approximately `C / N = 53.2 / 1 = 53.2 seconds`. The helper `max_regen_time_for_ability_charge` also divides threshold cost by the configured base regeneration; it does not replace the runtime update formula when regen buffs, drains or pauses apply. Cooldown bonuses and regeneration-speed bonuses affect different terms. [Base regeneration](https://github.com/Aussiemon/Darktide-Source-Code/blob/7e662fcda16219d775b84af50322be2e9cd9d62e/scripts/settings/ability/player_abilities/abilities/veteran_abilities.lua#L7-L24); [Base-regeneration time helper](https://github.com/Aussiemon/Darktide-Source-Code/blob/7e662fcda16219d775b84af50322be2e9cd9d62e/scripts/extension_systems/ability/player_unit_ability_extension.lua#L1297-L1320); [Runtime regeneration formula](https://github.com/Aussiemon/Darktide-Source-Code/blob/7e662fcda16219d775b84af50322be2e9cd9d62e/scripts/extension_systems/ability/player_unit_ability_extension.lua#L839-L880).

## Shared pool, usage and preserved progress

Maximum resource for a charge-based ability is `maximum charges × C`: **2 × 53.2 = 106.4 resource units** in the isolated example. From exactly zero resource with constant rate 1 and no use or other restoration, the first charge becomes available near 53.2 seconds and the second near 106.4 seconds. They restore sequentially at pool thresholds; they do not each run a separate 53.2-second timer in parallel. A full pool cannot bank additional recharge. [Maximum resource](https://github.com/Aussiemon/Darktide-Source-Code/blob/7e662fcda16219d775b84af50322be2e9cd9d62e/scripts/extension_systems/ability/player_unit_ability_extension.lua#L1323-L1348); [Resource update and thresholds](https://github.com/Aussiemon/Darktide-Source-Code/blob/7e662fcda16219d775b84af50322be2e9cd9d62e/scripts/extension_systems/ability/player_unit_ability_extension.lua#L839-L880).

The normal action uses one charge: `get_num_ability_charges_to_use` defaults both minimum and maximum usage to 1. `ActionBase._consume_ability_usage_cost` calls the ability extension, which selects the charge-use path. `consume_ability_charge` sends one threshold cost to `consume_ability_resource`; with neutral consumption stats this subtracts `C` while retaining fractional progress in the same pool. It does not clear and restart a separate countdown. [Action forwards usage cost](https://github.com/Aussiemon/Darktide-Source-Code/blob/7e662fcda16219d775b84af50322be2e9cd9d62e/scripts/extension_systems/weapon/actions/action_base.lua#L118-L123); [Charge-use path](https://github.com/Aussiemon/Darktide-Source-Code/blob/7e662fcda16219d775b84af50322be2e9cd9d62e/scripts/extension_systems/ability/player_unit_ability_extension.lua#L938-L965); [Default one-charge selection](https://github.com/Aussiemon/Darktide-Source-Code/blob/7e662fcda16219d775b84af50322be2e9cd9d62e/scripts/extension_systems/ability/player_unit_ability_extension.lua#L1487-L1511); [Charge resource consumption](https://github.com/Aussiemon/Darktide-Source-Code/blob/7e662fcda16219d775b84af50322be2e9cd9d62e/scripts/extension_systems/ability/player_unit_ability_extension.lua#L999-L1027); [Resource subtraction and charge recount](https://github.com/Aussiemon/Darktide-Source-Code/blob/7e662fcda16219d775b84af50322be2e9cd9d62e/scripts/extension_systems/ability/player_unit_ability_extension.lua#L1037-L1078).

The general consumption method can separately apply `combat_ability_resource_flat_consumed` and `combat_ability_resource_consumed_modifier`, then clamps the pool. `free_ability_use` bypasses normal consumption. Those are separate systems, not additional Overwatch output. The fixed examples assume no free use, no overrides and neutral consumption stats; otherwise the amount removed and the remaining progress must be recalculated. Infiltrate has no resource-pool override in its configuration. [Consumption modifiers and clamp](https://github.com/Aussiemon/Darktide-Source-Code/blob/7e662fcda16219d775b84af50322be2e9cd9d62e/scripts/extension_systems/ability/player_unit_ability_extension.lua#L1037-L1078); [Free-use branch](https://github.com/Aussiemon/Darktide-Source-Code/blob/7e662fcda16219d775b84af50322be2e9cd9d62e/scripts/extension_systems/ability/player_unit_ability_extension.lua#L938-L965); [Pool override lookup](https://github.com/Aussiemon/Darktide-Source-Code/blob/7e662fcda16219d775b84af50322be2e9cd9d62e/scripts/extension_systems/ability/player_unit_ability_extension.lua#L1364-L1380); [Infiltrate configuration](https://github.com/Aussiemon/Darktide-Source-Code/blob/7e662fcda16219d775b84af50322be2e9cd9d62e/scripts/settings/ability/player_abilities/abilities/veteran_abilities.lua#L73-L80).

### Controlled resource and time examples

Assume Infiltrate with Overwatch, capacity two, unchanged cost and regeneration, resource updates allowed, ordinary one-charge usage, and no other restoration or drain except where a row explicitly varies a stat. Times are seconds; pool values are resource units. Update boundaries and quantization make threshold times approximate.

| Assumptions | Substitution and result | Player meaning |
|---|---|---|
| One full charge missing, no other bonuses | `C = 40 × 1.33 = 53.2`; `N = 1`; time `53.2 / 1 = 53.2s`. | Each fully missing use takes about 53.2 seconds to recover. |
| Pool exactly zero, no uses during recovery | First threshold `53.2 / 1 = 53.2s`; full pool `2 × 53.2 = 106.4`, reached at `106.4 / 1 = 106.4s`. | The two stored uses refill in sequence, not simultaneously. |
| Start full, use once, wait 20s, then use the second charge | After first use `106.4 − 53.2 = 53.2`; after 20s `73.2`; after second use `73.2 − 53.2 = 20`; next deficit `53.2 − 20 = 33.2`, so another `33.2s`. | The second cast preserves the 20 seconds of accumulated progress. |
| One full charge missing, applicable +15% regen modifier only | `C = 53.2`; `N = 1 × 1.15`; time `53.2 / 1.15 ≈ 46.26s`; saved about `6.94s`, or `13.04%` versus 53.2s. | +15% regeneration speed is about 13.04% less refill time under these assumptions. |
| One full charge missing, other same-stage cost delta −0.20, no regen bonus | Without Overwatch `40 × 0.80 = 32`; with it `40 × (1 − 0.20 + 0.33) = 45.2`; time `45.2s`; increase `13.2 / 32 = 41.25%` versus 32s. | Overwatch adds 33 percentage points to the cost modifier; it need not mean 33% longer relative to an already modified cooldown. |

## Start time, stealth and capacity-change exceptions

Infiltrate's action requests cost consumption at **action start**. `ActionVeteranCombatAbility.start` calls the inherited start method; `ActionAbilityBase.start` consumes the cost and only requests a regen pause when the equipped ability has `pause_cooldown_settings`. The base configuration and Infiltrate clone have no such pause setting. Under the stated ordinary conditions, regeneration can therefore proceed after the cast creates a deficit, including during stealth; it does not wait for the invisibility effect to end. Other systems can still pause, disable or modify recovery. [Consume-at-start action settings](https://github.com/Aussiemon/Darktide-Source-Code/blob/7e662fcda16219d775b84af50322be2e9cd9d62e/scripts/settings/ability/ability_templates/veteran_stealth_combat_ability.lua#L90-L101); [Veteran action inheritance and start](https://github.com/Aussiemon/Darktide-Source-Code/blob/7e662fcda16219d775b84af50322be2e9cd9d62e/scripts/extension_systems/ability/actions/action_veteran_combat_ability.lua#L21-L36); [Cost and conditional pause at start](https://github.com/Aussiemon/Darktide-Source-Code/blob/7e662fcda16219d775b84af50322be2e9cd9d62e/scripts/extension_systems/weapon/actions/action_ability_base.lua#L8-L43); [Base ability configuration](https://github.com/Aussiemon/Darktide-Source-Code/blob/7e662fcda16219d775b84af50322be2e9cd9d62e/scripts/settings/ability/player_abilities/abilities/veteran_abilities.lua#L7-L24); [Infiltrate configuration](https://github.com/Aussiemon/Darktide-Source-Code/blob/7e662fcda16219d775b84af50322be2e9cd9d62e/scripts/settings/ability/player_abilities/abilities/veteran_abilities.lua#L73-L80); [Pause-aware update](https://github.com/Aussiemon/Darktide-Source-Code/blob/7e662fcda16219d775b84af50322be2e9cd9d62e/scripts/extension_systems/ability/player_unit_ability_extension.lua#L826-L860).

When capacity increases, the shared update may restore the added number of charges. Its respawn skip flag can suppress that grant, and the previous-capacity value also affects this branch. When capacity shrinks, the common update can limit charges/resource to the new maximum. Therefore equipping or respawning must not be described as an unconditional immediate refill to two uses. This dossier does not establish every live respec, spawn or loadout-transition sequence. [Capacity changes and respawn exception](https://github.com/Aussiemon/Darktide-Source-Code/blob/7e662fcda16219d775b84af50322be2e9cd9d62e/scripts/extension_systems/ability/player_unit_ability_extension.lua#L788-L824).
