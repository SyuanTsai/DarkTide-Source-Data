## 執行與計算

- 五個 own trait 的 I–IV 各自以 stat_buffs.ranged_power_level_modifier 提供 .14／.16／.18／.20；Buff 的條件統計計算仍讀取這份覆寫，替換 base conditional_stat_buffs 的備用值。實際 wrapper 沿用 power_bonus_on_first_shot，base 是持用槽位且 shooting_status.num_shots == 0 的條件式 Buff，fallback .02；等級值替換 fallback，不額外相加。

- Lasgun 的 tier.buffs 和 formatter 都選 weapon_trait_bespoke_autogun_p3_power_bonus_on_first_shot；全域 registry 匯入該 module，安裝流程使用這個實際 ID。Lasgun 自有同名 wrapper 雖有定義，此 trait 並未選取它。

- 共用 num_shots 初始化為 0。ActionShoot 通過彈藥檢查後準備射擊，非 simultaneous 的單發路徑會先增加 num_shots，再執行命中。Buff 系統先於武器系統更新，條件 stat 使用已計算的快取，所以不能把計數先增為 1 誤讀成首發沒有加成，也不能把同次射擊每個命中當成新首發。

- 清除條件為 not dont_clear_num_shots、num_shots > 0、not shooting，且 t > shooting_end_time + 當前 spread/movement 的 num_shots_clear_time；無 spread 或該欄位為空時用 0。計數清除發生於 weapon update，條件 stat 在後續 Buff 更新重新評估。裝填與切換未直接寫入 num_shots = 0。

- ranged_power_level_modifier 僅在 attack_type = ranged 時選入力量修正。Phosphor 一般射擊的 impact explosion 由 hit_scan 明確以 explosion type 建立，static_power_level = 500 覆寫傳入力量；DoT 另用 buff type，因此兩者都不選此 ranged 修正。

- 同一 fixed_update 的系統順序由 Gameplay 傳入 ordered config，ExtensionSystemHolder 按清單建立並依序呼叫；buff_system 先於 weapon_system。PlayerUnitBuffExtension 更新並重建 stat cache 後，PlayerUnitWeaponExtension 才更新 ActionHandler。所接入的11型號為 single mode，每次該 ActionShoot fixed_update 只有一個prepare/shoot分支；不推稱整個影格沒有其他獨立action component。

- WeaponMovementState 將離地映射到 moving，地面按速度與蹲伏分四種狀態。型號自己的 hip/aim action 選取各自 spread模板，狀態繼承在模板註冊前解析；重伐木槍的aim clear-time插值兩端相等。清除門檻在weapon動作更新後現讀，不是射擊快照；完整11型號數值集中在玩家說明。

- 設 S_native 為原始力量經對應力量類型的原生曲線轉換後、增益修正前的力量值；q 為其他適用力量修正的淨合計，p 為本祝福 .14／.16／.18／.20。來源先做原生曲線，再將適用修正相加，得到 S_after = S_native × (1 + q + p)。本項僅在 attack_type = ranged 時進入此式。

- S_native = 500、q = 0、IV p = .20 時，S_after = 500 × 1.20 = 600；等級值取代 .02 備用值，所以不是 610。

- q = .30 時，未套本項為 500 × 1.30 = 650，套用 IV 為 500 × 1.50 = 750；差 100，相對增幅約 15.38%。此例是力量輸入的比較，不是最終生命值傷害的比較。

- 修正後的力量各自進入 attack、impact、cleave 分布與後續曲線。磷光一般射擊的命中爆炸雖採 static Power 500，attack_type 卻是 explosion；燃燒為 buff。兩者都不使用 ranged_power_level_modifier，不能因為是同一把槍造成的追加傷害就套入上述首發遠程算式。
