## 執行與計算

- **持用條件與套用**：五個 wrapper clone `BaseWeaponTraitBuffTemplates.stagger_bonus_damage`；共用模板提供 `damage_vs_staggered=.20` 並由 `is_item_slot_wielded` 限定目前持用欄位。
- **Tier 覆寫**：每個 tier 在同名 conditional key 提供 `.05/.10/.15/.20`；Buff 取 tier override 替換基底 `.20`，不會先加 `.20` 再加 tier。
- **目標條件**：`DamageCalculation` 將 `num_triggered_staggers>0` 或 `count_as_staggered` keyword 視為符合；此 stat 不按輕／中／重踉蹌等級取值。
- **先後順序**：`Attack.execute` 算傷害前讀取目標現有 stagger component；傷害處理後才呼叫 `HitReaction.apply`，所以中性目標剛由該次攻擊造成首次踉蹌，不會令同一筆傷害回溯符合。
- **傷害階段**：`damage_vs_staggered` 是 `additive_multiplier`，本項加入攻擊者 damage-stat pool；同一函式也可能加入 target-side 同名 stat，該一般來源不是本祝福。最終傷害另經 damage-taken、finesse、hit-zone、護甲等階段。
- **狀態移除**：一般 `BtStaggerAction.leave` 清 `num_triggered_staggers`；該 action 監看新增計數並重進，不逐時遞減。具體的 `count_as_staggered` 例子是 Adamant 近戰弱點 debuff，持續 4 秒；此只證明替代 keyword 是效果限時，不是一般踉蹌時長。

- **間隔追加傷害**：重用已驗證同SHA的P2 on_equip primer→extra interval以及P4 shotgun_special_stun。各tick以仍存活owner為攻擊者，Attack即時讀stat_buffs，並非item存在才讀；Execution consumer不限定attack_type，故仍須當時目標踉蹌／替代keyword及held條件。P4 interval跳過staggered chaos_poxwalker_bomber。

- **爆彈配置限制**：兩份實際Bolt Pistol hitscan profile有hitmass kill/stop與penetration-stop爆炸，沒有armor_explosion配置；不因共通helper支持該路徑就聲稱這兩個型號也有護甲爆炸。

- **公式**：D前＝B×(1＋q)，D後＝B×(1＋q＋p)，增加量＝B×p，相對增幅＝p÷(1＋q)。B 為隔離主傷害，q 為其他同池淨加值，p 為本階級比例。

- **算例**：IV 級 B＝100、q＝0 為 100→120；q＝0.30 為 130→150，增加 20、相對約 15.38%。I–IV 在 q＝0 時為 105／110／115／120。

- **條件**：目標已符合踉蹌判定且武器持用；不含額外傷害部分、平加、破甲、背刺、側擊、轉換、上限或遞減，後續因素中性。最終整擊傷害保留其他結算，不能一律直接乘 1.05–1.20。
