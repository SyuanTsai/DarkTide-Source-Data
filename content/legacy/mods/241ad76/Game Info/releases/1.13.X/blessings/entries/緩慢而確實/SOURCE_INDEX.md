## 執行與計算

- 兩個 own tier 分別定義 I–IV `.05/.06/.07/.08`，formatter 以 percentage 加 `+` 前綴顯示 +5/+6/+7/+8%。兩個 wrapper 各自使用同型事件 callback；視覺 child 的 `max_stacks=3`、`stack_offset=-1` 不等同 `num_windup_procs`，實際回復乘數由自訂計數器 `min(counter,3)` 得出。
- `on_windup_trigger` 每處理一次便增加 `num_windup_procs`。Windup 首次觸發點取當前輸入可用連段中最大正值 `chain_time`；後續依 action 的 `proc_time_interval` 前進，未設定時採全域預設 0.25 秒。戰鎬綁定動作明列 0.20 秒，碎骨者使用預設值。這代表程式以離散事件計數近似蓄能，不是直接按已蓄能秒數作連續比例。
- `on_hit` 先確認 `params.attacking_item.name` 與祝福物品相同，再將 tier 比例乘計數上限 3、呼叫 `regain_toughness_proc_func` 並清零計數。此 callback 沒有檢查 attack type、melee strength 或目標種類；仍受持用條件、Attack 通用 profile／damage-type／dedup 事件資格、回復上限及原生恢復禁用條件影響。命中事件處理時計數才用於回復；不追溯命中前尚未處理的 windup 事件。
- 掃掠在進入傷害窗口後離開時會送 `on_sweep_finish`，即使沒有命中也重置計數；在傷害窗口開始前取消不經此完成路徑。重新持用也清零。沒有自訂 TTL 或冷卻；child 僅為 HUD 計數提示，並非回復狀態本身。
- 三種戰鎬一般輕／重動作具有各自 windup/chain_time；其特殊招式是直接 sweep，並不產生自己的 windup 事件。碎骨者普通輕／重及兩個 weapon special 分支均先經 windup 再進入 sweep。Push 是獨立 action kind，不產生 windup。四種實際 push action 把目前 weapon item 傳給 PushAttack；命中使用 `ogryn_push` 或 `default_push`，Attack.execute 以 attack_type=push 結算後，除另送 `on_push_hit` 外，也會在一般 Attack profile／damage-type／dedup 條件通過時送 `on_hit`。本祝福聽 `on_hit`，所以若同物品且仍有 windup 計數，純推擊可以消耗舊計數；純推擊本身不增加計數。
- 回復輔助函式按最大韌性比例計算，乘計數後呼叫原生 `recover_percentage_toughness(..., true)`；true 會略過一般回復倍率，但仍檢查存活、倒地（只有 force_assist 才跳過此檢查）、prevent-replenish 關鍵字與 ability-only 回復條件。此 helper 傳入 reason=nil，不能使用只允許特定能力回復的例外。

單次命中要求回復 `W=M×p×min(n,3)`，實際回復 `R=min(M−T,W)`；`M` 為最大韌性、`T` 為命中前韌性、`p` 為階級比例、`n` 為先前已處理的 windup 門檻數。命中後自訂計數歸零。`ignore_stat_buffs=true` 只跳過一般回復倍率，原生回復禁用條件仍有效。
