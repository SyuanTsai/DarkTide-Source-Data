## 執行與計算

九個實作的 Buff wrapper 各自只 clone 同一個 `toughness_recovery_on_chained_attacks` 基礎模板；沒有後續 wrapper 覆寫。基礎模板是非預測 ProcBuff，監聽 `on_sweep_finish`，限制為來源武器槽在手持槽。它以 `params.num_hit_units > 0 and params.combo_count > 0` 決定遞增或重設內部計數器；計數器大於 1 才讀取本武器的 tier override，並以 `ignore_stat_buffs=true` 呼叫 `recover_percentage_toughness`。這是即時韌性回復，不是將韌性恢復 stat 暫時加成。

ActionSweep 在目標命中登記時快照其是否存活，之後才執行該目標的傷害計算；結束事件仍以此快照所累積的直接存活角色命中數與 Sweep 開始時捕捉的 combo_count 建立。因此本次 Sweep 擊殺原先存活的目標仍可計入，且不要求造成正生命值傷害。動作處理器先把當時 combo_count 傳給新動作，之後才按實際 action kind 更新連擊數；因此必須以該次 Sweep 的快照判斷，不能從下一動作的連擊數倒推。純推擊（實際 action kind 為 `push`）本身不走這個事件；部分推後攻擊雖由推擊引出，但若該 Mark 的實際後續 action kind 為 `sweep`，就會照一般 Sweep 規則送出結束事件。獨立 WeaponShout 不走這個事件。特殊類別回呼與 on_sweep_finish 分開；附著爆炸或電弧等次級目標不會另產生 Sweep 結束事件。

Buff 由武器 on_equip 加入；`is_item_slot_wielded` 在事件處理時檢查其 item slot。單純切槽不會移除 on_equip Buff，切槽期間條件不通過；卸下／移除裝備才清除此 Buff。`recover_percentage_toughness` 使用當前最大韌性乘 tier 百分比，忽略 toughness replenishment stat 倍率並將實際回復限制在缺少韌性，regen disabled 時回 0。

令 `T` 為當下計算出的最大韌性，`M` 為目前缺少韌性，`p` 為此實作與等級的 `toughness_fixed_percentage`。在韌性恢復未被狀態停用時，本次實際回復為 `min(M, T × p)`；若狀態停用，結果為 0。基礎模板以 `ignore_stat_buffs=true` 呼叫，因此不再乘 `toughness_replenish_modifier` 或 `toughness_replenish_multiplier`；`T` 本身仍採當前 `max_toughness()` 計算結果。

每一個已處理的 `on_sweep_finish` 事件先更新內部計數器：命中數大於 0 且 Sweep 開始時 `combo_count > 0` 時加 1，否則設為 1。僅計數器大於 1 才執行上式。這個計數器與 ProcBuff `max_stacks=1` 是兩件事；max_stacks 限制 Buff 實例數，不限制內部計數值。
