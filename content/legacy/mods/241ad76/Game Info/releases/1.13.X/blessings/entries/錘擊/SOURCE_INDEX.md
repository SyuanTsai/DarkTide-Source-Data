## 執行與計算

九個實作都各自 clone 同一父／子模板並接回自己的 child；各 own tier 對 `melee_impact_modifier` 的同鍵覆寫取代基礎子模板 0.20 fallback。父層接受 `on_hit`，以來源物品比對和持用條件限制加層，最多五個有效層。`stack_offset=-1` 使初始化佔位 child 等效為零層；每次 accepted event 新增一個 child 並重設共同計時。嚴格到期後 parent 一次移除五個有效層。

`Attack._handle_buffs` 在 profile 未設定 `skip_on_hit_proc` 且 damage type 可處理時建立 `on_hit`；此處不限制 `attack_type` 或正傷害量。純推擊並非只有 `on_push_finish`：實際 ActionPush 將原武器 item 傳入 PushAttack，PushAttack 依當次 inner/outer 方向選擇 profile，逐個目標以 `attack_type=push` 和原 item 呼叫 `Attack.execute`，再由 ActionPush 另行發出 `on_push_finish`。本九個實際推擊 profile 均未設定 skip flag，因此在 item／held 條件通過時，推擊命中也能加本項層數。

父層不要求 attack_type，但 `melee_impact_modifier` 只由近戰攻擊的 stagger／impact 計算讀取；純推擊可加層但本身不受此修正，推擊後 sweep 是獨立 melee 攻擊。直接 sweep 與 sticky tick 都以 melee 和原武器 item 呼叫 `Attack.execute`；Powermaul P1 的 sticky profile 明確跳過 `on_hit`，仍可能在 buff 有效時使用當前 melee impact cache。電弧錘 shout／arc 與錘盾 shout 可送來源物品命中事件，但不消費近戰衝擊修正。更新順序是先更新現有 buff，再處理 proc 事件，最後重建 stat cache。

令 `n` 為 0–5 個有效層，`t` 為每層 tier 修正（I／II／III／IV = 0.19／0.21／0.23／0.25）。在其他近戰衝擊修正中性的前提下，本項的 `melee_impact_modifier` 項為 `1 + n×t`；滿層分別是 1.95／2.05／2.15／2.25。它是衝擊結算輸入，不是最終踉蹌比例，更不是目標生命傷害或命中質量。

同鍵 tier 覆寫替代基礎 child 的 0.20 fallback，不是 `0.20+t`。固定更新中命中先以舊快取結算，`on_hit` 後才加入層並更新快取，所以新層從後續快取生效。
