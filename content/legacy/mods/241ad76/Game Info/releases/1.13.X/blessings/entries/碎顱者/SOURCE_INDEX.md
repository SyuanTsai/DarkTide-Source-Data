## 執行與計算

來源 parent 的命中事件使用 `on_stagger_hit` 檢查目標是否屬 Minion 分類，以及事件處理當下的 `MinionState.is_staggered(target)`；目標 helper 另要求目標仍存活且有 buff extension。同時比較事件攻擊物品與祝福來源物品，並要求來源武器目前持用。此觸發條件不要求擊殺、正生命傷害或特定 melee/ranged attack type。

施加流程與傷害消費流程分開。Attack 先計算該次傷害，HitReaction 更新踉蹌狀態後，attacker 的 `on_hit` 才被處理，所以同一擊即使新造成踉蹌並加上 debuff，也不能追溯改寫已結算傷害。目標端 `increase_damage_received_while_staggered` 有 5 秒期限、每次新增刷新期限，並提供 conditional `damage_vs_staggered=0.1`。目標 stat aggregation 將 stack_count 加 offset 後 clamp 到 8；模板沒有 `max_stacks_cap`，故 8 是有效 stat 層上限，不足以證明實體 stack_count 也封頂 8。父 helper 的 31 是原始累積請求上限，和 stat clamp 分開；達到 31 後，合格命中即使本次請求被截為 0 層，helper 仍呼叫期限刷新。

目標 buff 在目標自己的 BuffExtension 更新中加入並重建 stat cache。來源武器切出會使來源持用條件不再通過，但不會移除其他單位身上的既有目標 debuff。傷害消費時，DamageCalculation 以 `num_triggered_staggers>0` 或目標的 `count_as_staggered` keyword 建立 `target_is_staggered`，再將攻擊者和目標的 `damage_vs_staggered` 加入傷害池；它不直接呼叫 MinionState。這是消費端條件，與來源 proc 的 live `MinionState.is_staggered` 檢查不同。

一般輕重擊與實際命中都依 Attack 事件處理。特殊路由逐型號已核：工兵鏟 Mk I 特殊上刺；Mk III／Mk VII 折鏟特殊輕、重揮擊及其 light/heavy sticky 追加命中，sticky 事件帶原武器物品且其設定 profile 未設 skip。惡魔之爪特殊反擊的揮擊才是命中。廁所鏟 Mk III 特殊上刺，Mk XIX／Mk V 折鏟特殊輕重揮擊；惡霸棍棒兩個特殊 slap 動作均為 sweep。動力錘及碾壓者的特殊 impact class 會在符合條件時另建立爆炸 Attack，爆炸使用原武器物品並帶 `attack_type=explosion`，每個實際爆炸命中仍單獨檢查。電擊錘直接 `axe_uppercut` 可走 Attack；其黏附 tick 的 `powermaul_weapon_special` profile 明確 `skip_on_hit_proc=true`，不觸發。雷鎚的特殊啟動是 activation，充能後 sweep 的 active profile 命中才走 Attack。作戰大錘&板盾的特殊動作 `kind=block`，格擋本身不是攻擊命中。各型號推擊都有攻擊 profile；只有該次真的進入 Attack.execute 並派發 on_hit 才可觸發，獨立 push event 不行。

令目標端有效層數 `N=clamp(stack_count+stack_offset,0,8)`，目標仍符合傷害計算的踉蹌門檻時，單項傷害池倍率為 `1+0.10×N`。每次通過來源事件檢查時，Tier I／II／III／IV 分別請求 1／2／3／4 層；該次傷害已在 on_hit 之前計算，新層只能在目標 buff 更新快取後供後續傷害讀取。以上例子使用 `D0=100` 作正規化的傷害階段輸入，profile、防護與其餘傷害池因素保持中性，因此不代表遊戲固定傷害或最終 HP 百分比。
