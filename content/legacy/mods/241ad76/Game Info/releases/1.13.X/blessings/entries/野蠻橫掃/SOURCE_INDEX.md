## 執行與計算

- 本實作複製 `BaseWeaponTraitBuffTemplates.increased_attack_cleave_on_multiple_hits`：`class_name="proc_buff"`、事件 `on_hit`、活動時間3秒、允許活動中再次觸發、`required_num_hits=3`、held item slot 條件，並以 `on_item_match` 與 `on_multiple_melee_hit` 串接。
- `on_multiple_melee_hit` 讀取目前事件的 `attack_type` 和 `target_number`：必須是 melee 且 `target_number >= 3`。ActionSweep於處理碰撞時遞增 `num_hit_enemies`，將目前序號傳給 Attack.execute；這不是「已成功送出三次 on_hit」的累積計數。
- Attack._handle_buffs只在實際 on_hit 分支排入事件；傷害profile的 `skip_on_hit_proc`、damage type等共通條件仍適用。事件加入佇列本身不會要求本次有正傷害或踉蹌。純 push 使用 push攻擊類型與 `on_push_finish`，不符合；push-follow及直接 special sweep 是 sweep/melee，可在其他條件成立時符合。
- ActionSweep在開始時先算攻擊／衝擊最大命中質量。其後的第三目標事件經 ProcBuff處理並更新stat cache，不能回頭改變目前掃擊；之後開始的掃擊才讀到已更新值。
- 每次合格事件都可於活動期間再觸發；事件處理時刷新active_start_time，不加層。切出時held-slot條件關閉，時間繼續流逝；只要祝福buff仍安裝且未逾時，切回後才重新符合條件。

記A為其他既有力量／蓄力／profile因素計算出的攻擊側基礎max hit mass，I為衝擊側基礎max hit mass。只有本祝福、其他修正中性時：

- `A′ = A × (1 + t)`，其中標準五實作 I–IV 的`t`為1.4／1.6／1.8／2.0，穿音速雙刀為1.2／1.3／1.4／1.5。
- `I′ = I`；本祝福不改衝擊側stat。
- `ActionSweep有效max hit mass = max(A′, I′)`。攻擊、衝擊本身仍受profile/力量曲線及其他修正影響；例子中的A與I是那些前置計算完成後的基礎輸入。

 tier raw值直接加至中性值1的`max_hit_mass_attack_modifier`。own tier覆寫ProcBuff fallback .5，而不是再加在fallback上；故例中I級標示+140%對應攻擊側2.4倍基準。這是順劈質量倍率，不能乘到生命傷害。
