## 執行與計算

- 兩個實際標記共用同一個祝福 ID；等級資料以 `cooldown_duration` 覆寫基底冷卻。Trait Value 定義使用 `number` formatter，RAW 的秒字樣來自描述句型，無百分比格式。
- Trait wrapper 單純複製 `BaseWeaponTraitBuffTemplates.wind_slash_crits`。實際 Buff 為 ProcBuff，訂閱掃掠開始事件，冷卻就緒且事件攜帶特殊模式啟用旗標時通過；回呼不要求命中、不比較攻擊物品，也沒有持用條件。基底模板的 `proc_func` 為空，沒有另外建立祝福效果層。
- Buff 初始化以當前起始時間減去 active duration 與冷卻作為初始時間；本模板沒有 duration 或 active-duration 覆寫，I–IV 的冷卻覆寫分別為 30、25、20、15 秒。有效事件將 active-start-time 設為事件時間；條件關鍵字依 ProcBuff 的 readiness context 在 Buff 關鍵字重建時加入或移除，因此冷卻之外沒有第二個 TTL。ProcBuff.update 才會依冷卻狀態更新 template_context.active；事件處理只記錄 _active_start_time，不會同步改該 context。
- ActionSweep 在掃掠開始時讀取目前 inventory slot 的 `special_active`，把布林值放入 on-sweep-start 事件；事件在攻擊命中前送出。純 push、target-finder、damage-target 路徑不是 ActionSweep 起始事件；兩個實際 action table 沒有 throw 或 projectile kind。
- Trait 會由實際 weapon trait 組裝路徑放到 on-equip buff 清單；切換 slot 時只處理 on-wield／on-unwield 清單，所以仍裝備在其他 slot 時，別的武器之 powered sweep 可能消耗此冷卻。該 trait clone 沒有 item-slot-held gate。一般移除／卸下該 weapon slot 才移除它的 externally controlled trait buff。
- 風斬由力場巨劍自己的 special primer 選擇低／中／高層級，門檻為特殊充能 0／10／20；其獨立 trigger buff 另外要求該 item slot 正持用並且 sweep 事件中的特殊模式旗標為真。Trigger 會立即加入內部 wind-slash effect，並關閉特殊模式。Effect buff 的 start callback 立即快照一般暴擊狀態或當前保證風斬暴擊關鍵字；固定更新先更新 Buff、再處理排隊 proc event、最後重建 keyword cache。若該批事件啟動冷卻，當批尾端的 cache 可能仍保留舊就緒關鍵字；要等後續 ProcBuff.update 把 context.active 設為 false，並在其後重建 cache 才移除。冷卻到期時也要等一次尾端 cache rebuild 才能讓新的 native effect 讀到保證暴擊關鍵字；在那之前建立者仍讀舊 cache。
- 已建立的 slash 保存目標清單、傷害 profile、方向和暴擊旗標；發射前若不再持用會清除待發狀態，發射後依 saved hits 與剩餘路徑繼續。目標命中透過 RangedAction.execute_attack 傳入該旗標；這是一個 attack_type.ranged 的傷害消費路徑，不是 projectile-unit 生成路徑。
- M1、M2 都使用 30 單位範圍、0.25 秒起始延遲、0.75 秒行程和相同三組風斬傷害 profile／damage type；M1 厚度 0.5、M2 厚度 0.25。上述充能門檻與風斬 profile 選擇屬武器特殊能力，不是本祝福等級值。


I–IV 直接讀取各自 trait override 的 `cooldown_duration`：30、25、20、15 秒。若符合條件的掃掠開始事件在時間 t 通過 ProcBuff 檢查，冷卻由該事件時間開始，下一次就緒門檻為 t+該級秒數；不是從命中或風斬結束時計算。

此祝福沒有百分比增量、期望暴擊率或最終傷害倍率可計算。保證暴擊只在風斬建立時把當前一般暴擊狀態或已快取的保證關鍵字保存為布林旗標，之後的風斬命中沿用該旗標。若事件處理後才重建 keyword cache，不能用稍後才出現的快取值回頭替已建立的風斬補上暴擊。
