# 激勵彈幕(Inspiring Barrage)

[祝福目錄](../../README.md)｜[來源與公式](SOURCE_INDEX.md)

<img src="https://github.com/user-attachments/assets/6b381aff-25ca-43bb-9878-356963df97f5" width="72" height="72" alt="激勵彈幕祝福圖示">

- **觸發方式**：裝備反衝者 洛倫茲 Mk V 或惡棍槍 洛倫茲 Mk VII 並手持該武器。只有彈藥事件被處理時正持用該武器、且連擊計數條件成立，才直接回復韌性；持用以事件處理當下的槽位為準，不再比對事件來源 item／slot；不要求子彈命中、擊殺、弱點或爆擊。

- **連擊計數條件**：不是每個連擊計數大於 0 的射擊都會回復。事件處理時，當前連擊數 n 必須高於前次彈藥事件記錄值，或等於原生上限 m = NetworkConstants.action_combo_count.max；每次檢查後都會把記錄更新為當時的 n。若動作重設後 n 回到較低值，或回到小於 m 的相同值，該次不會通過；但 n = m 仍符合上限分支。之後須達到 n > 前次記錄值或 n = m 才會通過。這個原生計數上限與單次回復倍率最多乘 5 是不同條件。

- **回復量**：I、II、III、IV 級每個連擊計數單位分別回復最大韌性的 1%、2%、3%、4%；計算最多乘上 5。它是一次直接韌性回復，不會留下一個持續中的韌性加成或 5 層 Buff。

- **計數方式**：程式讀取武器動作的連擊計數，不是累計命中的彈丸數。反衝者的每次散射射擊只產生一個彈藥事件，惡棍槍的 hitscan 射擊也相同；一發中有多顆彈丸或命中多個目標，不會按彈丸或目標重複回復。

- **第一次回復**：效果在一個通過連擊條件的彈藥事件被處理後才發生，Buff 更新後才可反映到韌性。反衝者兩種射擊都有保留連擊的設定；惡棍槍從閒置開始的首個射擊動作會依原生規則把計數重設為 0，之後須由實際連擊鏈推進計數才可能回復。

- **兩把槍的連擊差異**：反衝者的腰射與瞄準射擊皆設 keep_combo_on_start=true，瞄準和裝填會 hold_combo；惡棍槍的兩種射擊沒有 keep_combo_on_start，瞄準也沒有 hold_combo，裝填會保留計數。逾時計數重設只會在非迴圈動作結束後，經過的時間超過設定值時發生：反衝者為 0.5 秒，惡棍槍使用原生預設 0.2 秒。不是每次射擊後固定倒數；動作鏈的 reset、keep 或 hold 設定也可能更早改變連擊數。

- **其他攻擊**：普通 Bash 是近戰 Sweep，可影響武器原生連擊計數，但不消耗彈藥，所以 Bash 本身不直接回復韌性；某些 Bash 銜接會重設連擊。推擊、投擲、爆炸、附加傷害和其它命中結果不會代替這兩把槍的彈藥事件觸發祝福。

- **時間與切換**：祝福沒有自身的持續時間、冷卻或可累積的 Buff 層數；延續或重設的是武器動作連擊計數。切出後目前持用條件關閉，不能從這把武器觸發新回復；切槽本身不會清除祝福記錄的前次彈藥事件連擊數。切回後不保證下一發回復，仍須依記錄值、原生連擊數與上述通過條件判斷。

- **卸下與韌性限制**：武器從裝備槽移除時，該武器的 on_equip Buff 也會移除。韌性已滿時沒有可回復缺額；一般倒地且 force_assist=false 會阻止韌性回復，force_assist=true 不受這一項倒地封鎖，但其它原生回復限制仍適用。

## 計算與算例

- **前提**：假設 IV 級反衝者的最大韌性為 100，目前為 70；上一個合格彈藥事件記錄的連擊數是 3，本次事件處理時連擊計數升至 4，角色不處於回復封鎖狀態。

- **代入**：每單位回復 100 × 0.04 = 4；連擊倍率為 min(4, 5) = 4；因此計算量為 4 × 4 = 16 韌性。當前缺額為 100 − 70 = 30，16 沒有超過缺額。

- **結果**：本次直接回復 16，韌性由 70 到 86。

- **玩家意義**：4 是事件處理當下的武器連擊計數，不是四顆彈丸命中或四個敵人；恢復不會變成一個持續的 16 點加成。

- **前提**：假設 II 級惡棍槍的最大韌性為 100，目前為 94；上一個合格彈藥事件記錄的連擊數是 4，本次射擊事件讀到連擊計數 5，並且角色可正常回復韌性。

- **代入**：計算量為 100 × 0.02 × min(5, 5) = 10；當前缺額只有 100 − 94 = 6。

- **結果**：回復受缺額限制為 6，韌性到 100，而不是超過上限到 104。

- **玩家意義**：五倍是單次計算倍率上限，不會讓回復越過最大韌性；若韌性已滿，本次實際回復為 0。
