## 執行與計算

本項不是「每次舉盾」或「每次推擊」觸發；盾錘物品在裝備時安裝 ProcBuff。原生入站鏈是 blocked hit → Block.attempt_block_break → stamina drain → 玩家 weapon extension 排入 on_block(block_broken)。兩個獨立 wrapper 都只聽 on_block；在事件被 ProcBuff 處理時要求來源 item slot 正在手持，並再次要求 params.block_broken。block_broken 精確定義為 stamina_depleted 且 block_cost>0。

普通 block action 對四個實際 Mark 都允許 melee/ranged，另外還需 action block component、角度和有效 block cost。Slab Shield M1/M2 的 action_weapon_special 雖是 weapon_special block 並能接 melee/ranged，但 block_goes_brrr 將 block_cost 強制歸零，所以該特殊格擋不可能滿足本項；standard action_block 沒有這個零成本覆寫。Shock Maul Shield M1/M2 的 action_special_start 是 ActionBlockWindup，繼承 ActionBlock.start 的 is_blocking；轉成 weapon_shout 時，ActionBlock.finish 保留 blocking，weapon_shout 以 block_duration=.4s 清掉，兩段都允許 melee/ranged 並可能發生真正的 block break。它的特殊推吼本身是向外攻擊，不是本項 on_block 事件。

一般 push/pushfollow 是向外動作，不送 on_block，也不能自行觸發。本項四個 Mark 的推擊鏈可分別保留原有格擋狀態 0.5 秒（Slabshield）或 0.4 秒（Shock Maul Shield）；只有這段時間內確有來襲攻擊、當前動作接受該 melee/ranged 類型與角度、攻擊被成功格擋，且正格擋消耗耗盡耐力，才可能排入本項推擊。

ProcBuff 在處理合格 on_block 事件時先把 template_data.perform_push 設為 true。兩個 wrapper 的 update_func 下一次執行時只檢查該旗標：先清除旗標，再讀取當時的 locomotion position 與 first-person rotation 並呼叫 PushAttack.push；它不會再次檢查 held 條件。於是切槽若發生在事件處理之前會阻止新的觸發；若已設下待發標記，單純切槽不取消該推擊，來源祝福仍安裝時後續更新照常發出。真正卸下武器會移除 on_equip buff 並刪除該武器實例，該來源的 block-cost stat、冷卻和待發標記都不再保留。

兩個 wrapper 都把 on_block proc 記成單次 perform_push；更新函式清除旗標後呼叫 PushAttack.push。其私有設定是半徑 5，內角 .55π 使用 ogryn_shield_push、外角 π 使用 default_shield_push，均為 physical damage_type。API 對 overlap 結果按角度選 profile、略過 death-manager-owned 與重複單位，並以 attack_type=push 對目標執行；不把 1000 PowerLevel 輸入解讀成固定傷害。

block_cost_multiplier 寫在普通 stat_buffs，沒有 conditional_stat_buffs/held-gate；來源項目裝備後它進入防守者的 block-cost 計算。ProcBuff 的 held-slot 條件只限制新事件是否可啟動；玩家換手時不移除 on_equip stat，仍安裝的祝福也保留冷卻與已排程旗標。每次成功事件處理時設定 active_start_time=t，冷卻按該級 cooldown_duration 計；初始 ProcBuff 將 active_start_time 設在 start_time−cooldown，因此首次事件不需先等一輪。

令 C 為已套用攻擊 profile 的 block_cost、block_cost_multiplier 為本級倍率 b。中性其他修正時，最後送入耐力消耗的量為 C×b；block_broken 仍由 current_stamina≤該量且 block_cost>0 決定。b 依 I–IV 為 .85/.80/.75/.70，對應 −15/−20/−25/−30% 格擋消耗；示例採 C=1.00、current_stamina=.72。這是耐力成本比例，不是傷害減免；本項推擊參數 power_level=2×DEFAULT_POWER_LEVEL=1000 只是 PowerLevel 輸入。
