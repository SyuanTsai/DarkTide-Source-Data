## 執行與計算

- **條件來源**：base template 是 class buff；ConditionalFunctions.is_item_slot_wielded 與 ConditionalFunctions.melee_weapon_special_active 同時為真，才提供兩個 conditional keyword 與 conditional heavy-damage stat。前者比對實際持用欄位，後者讀該欄位的 special_active。
- **等級覆寫**：P1/P3 wrapper 各自 clone 對應 base；自己的 tier 對 melee_heavy_damage 同 key 覆寫 .05 fallback，不是與 .05 相加，所以布蘭克斯 I 是 .04。沒有本祝福的命中 proc、額外層數或獨立 TTL。
- **掃擊處理**：ActionSweep 讀取 use_reduced_hit_mass 和 ignore_armor_aborts_attack。這會略過 armor-abort；max_hit_mass 與 _breed_aborts_attack 是另外的中止條件。HitMass 只把活著、非玩家、非 prop、非 living-prop 的敵方 breed character 乘 .25；玩家、prop、dead target 仍走各自分支。
- **傷害結算**：DamageCalculation 僅在 melee attack 且 profile strength 為 heavy 時使用 melee_heavy_damage。它加入 damage-stat 修正池，再與目標承傷修正及後續倍率組裝；目標 armor type 仍交給傷害計算。這項重擊加成不會轉成輕斬直接加傷。
- **動作接線**：P1 斯干達／阿克利斯的實際 special-active sweep profiles、純 push 與 push-follow 依兩個 mark 的 action graph 核對；P3 布蘭克斯的八個 special action→active profile 連線逐一核對。P3 純推擊是 kind = push；action_pushfollow 是一般輕斬 sweep profile。
- **原生特殊狀態與首次生效**：P1 為 3 秒單次攻擊窗，可在作用中重新啟用，切出時關閉狀態；P3 為 4 秒、最多 6 格充能，啟用消耗一格，自訂卸用 callback 可保留剩餘充能。兩者都仍須滿足持用與 special_active 快取條件；欄位切換／狀態變更依 buff-cache 更新後反映，不保證同一呼叫邊界同步。

主控差異補證：P1十四條已驗收特殊狀態揮擊路由的五個實際設定，沿各自直接melee_attack_strength與完整父設定覆寫路徑解析；共七個設定／父設定來源。兩個推擊追擊均為light，沒有由名稱light推定；與P3推擊追擊的已證light強度一致。持用條件與inventory special_active控制本祝福；原生狀態、已保存充能與效果快取是不同層次，切出P3保留充能不代表當前效果仍作用。

- **傷害修正池**：令 p 為本祝福值、q 為其他 damage-stat 修正總和、B 為該重擊在這個修正池前的基礎傷害，d 為之後目標承傷與其他乘數。程式將 p 加入同一傷害修正池，示意式為 B × (1 + q + p) × d；不是把最後生命值無條件乘上 (1+p)。
- **等級值**：P1 p ∈ {0.05, 0.10, 0.15, 0.20}；P3 p ∈ {0.04, 0.06, 0.08, 0.10}。實際門檻是武器在手、特殊狀態 active、melee 且 profile strength heavy。
- **隔離算例**：令 B=100 是非弱點、非爆擊的修正池前傷害，q=0 且 d=1；P1 IV 得 100 × (1+0.20)=120，P3 IV 得 100 × (1+0.10)=110。若有其他同池修正，p 只作加算；若有額外傷害、弱點／爆擊與目標承傷乘區，需另代入完整公式。
- **受擊質量與中止**：對合資格活著敵方 breed character，hit_mass' = hit_mass × 0.25 × target_hit_mass_modifiers；動作仍以 current_amount + target_hit_mass × action_armor_hit_mass_mod 累計。略過 armor-abort 不會關閉 max_hit_mass 或 breed-abort。
