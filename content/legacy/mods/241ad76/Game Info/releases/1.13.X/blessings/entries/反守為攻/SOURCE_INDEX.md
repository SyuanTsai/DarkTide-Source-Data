## 執行與計算

來源 Buff 在裝備武器時建立；兩個 wrapper 都以 `on_block` 與 `on_sweep_finish` 作為輸入，且持用條件套在事件處理與子效果上。格擋事件流程是有效格擋 → `Block.attempt_block_break` 計算原始 `block_cost` → `Stamina.drain` 可能乘 `stamina_cost_multiplier` 並把耐力歸零截斷 → `PlayerUnitWeaponExtension.player_blocked_attack` 以原始 `block_cost` 排入 `on_block`。因此它累積的是事件傳入成本，不是從耐力條事後量測的實扣值；wrapper 沒檢查 `block_broken`。

首次生效有事件與快取兩個步驟：`on_block` 先由武器端排入玩家 BuffSystem；下一次玩家 Buff fixed update 處理事件後，會在同一更新重建 stat-buff 快取。Extension system 設定與 holder 依序建立、執行 fixed-update 清單，BuffSystem 排在 WeaponSystem 前；因此之後才進行的武器威力計算會讀到新層，格擋當下已計算完成的攻擊不會回溯套用。

兩份父 wrapper 分別明確接同名 `on_block`／`on_sweep_finish`，`allow_proc_while_active=true`。格擋時計算 `T=(T or 0)+params.block_cost`；若從前一 `last_hit_time` 到現在大於3.5秒，則改為當次 `block_cost`。之後 `k=clamp(floor(T)+(T>0 and 1 or 0),0,5)` 並刷新時間。掃掠完成時，不管命中數量，分別令 `T=max(T-1,0)`、`k=max(k-1,0)` 並刷新同一時間。`ActionSweep` 只在傷害窗已開始且到終點／最後幀／該窗掃掠全部中止時送出完成事件；未進傷害窗便取消不走該完成路徑。純 `ActionPush` 是不同 kind，不會發此事件；型號中的 push-follow 是 sweep。一般推擊仍可保留來襲格擋窗口：板盾兩 Mark 為0.5秒、鎮壓護盾兩 Mark 為0.4秒；窗口內成功格擋的來襲攻擊仍可送出 `on_block`，但推擊本身不增 `T`。

Target-number parent 每個 `k` 對應一個有效子層，另有一個 `stack_offset=-1` 佔位層；有效上限5。持續時間3.5秒是父層共享時鐘，不是每層各自倒數。嚴格超時時，目標有效層歸零但父資料的 `T` 和時間標記仍保存；事件順序可能使過期後的掃掠更新該殘留值與時鐘。零成本 `on_block` 不加 `T`，但若未觸發超時重置，仍依保留 `T` 重算 `k`，所以不能把它概括成永遠不改變有效層數。

父子條件以本物品是否手持控制；切槽不會立刻移除 on-equip buff，子層在下一次快取更新時停止提供屬性，時鐘仍走，切回且層未過期後再參與屬性快取。真正卸下武器才刪除該 buff 實例。PowerLevel 消費端只在 `attack_type=melee` 讀 `melee_power_level_modifier`；純推擊使用 `attack_type=push`，不吃這個近戰威力修正；掃掠與推擊追擊仍是近戰掃掠。

兩個盾牌特殊的放出行為不同：板盾 M1／M2 特殊格擋是 `kind=block` 且 `block_goes_brrr` 令原始成本為零，窗口內的來襲攻擊仍可送零成本 `on_block`。鎮壓護盾 Mk VI／Mk XI 的 release 是 `kind=weapon_shout`，放出動作開始時保留0.4秒格擋窗口，推吼在動作開始後0.25秒發出並與窗口重疊；其完整 action settings 未設 `attack_type`，`ActionWeaponShout` 讀取並傳遞 nil 給 `Attack.execute`，而 `PowerLevel.power_level_buff_modifier` 只有在攻擊類型等於 melee 時才取本項 modifier，所以推吼不讀本項近戰威力修正。該 action 不是 `ActionSweep`，不會送 `on_sweep_finish`；release 自身不消耗一層，但其0.4秒 block window 接住的 incoming attack 仍可觸發 `on_block`。

- 兩份實際 wrapper 的回呼不另外比對事件來源 item；本項的事件處理條件是處理時來源武器欄位仍被持用。

令 `C=block_cost`（本項收到的格擋事件參數），`T` 為最近一次有效處理前的累積值，`k` 為有效層，`p` 是每層本級近戰威力修正，`B` 是已通過原生 PowerLevel 曲線、尚未乘祝福／其他威力修正的輸入，`q` 是同一威力修正池中的其他加成。

`on_block`: 若 `t-last_hit_time>3.5`，`T'=C`；否則 `T'=T+C`。接著 `k'=clamp(floor(T')+(T'>0?1:0),0,5)` 並設 `last_hit_time=t`。`on_sweep_finish`: `T'=max(T-1,0)`、`k'=max(k-1,0)`、`last_hit_time=t`。超時移除有效子層時不清除此父層 `T`。

威力階段的簡化倍率是 `1+k×p+q`，`P=B×(1+k×p+q)`。例（兩層，k=2）：IV `p=.10`、`k=2`、`B=500`、`q=0`，則 `P=500×1.20=600`。這只說明威力輸入池的相對變化，不是最終生命傷害公式。
