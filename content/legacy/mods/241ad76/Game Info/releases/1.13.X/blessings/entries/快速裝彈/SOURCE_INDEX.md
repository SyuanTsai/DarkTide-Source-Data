## 執行與計算

- 固定版本的 inventory/UI 對應為12個 trait 實作、23個實際型號 binding，全部屬遠程武器。每個武器都有自己的完整 trait ID與 weapon_type_restriction；本項圖示使用實際 `item.icon` 路徑 `content/ui/textures/icons/traits/weapon_trait_117`，附件 URL 獨立記錄。
- 11個 wrapper clone `reload_speed_on_close_kill_parent` 與 child；該父層監聽 `on_kill`，要求同一攻擊武器、死亡結果、遠程攻擊或明確 count-as-ranged profile，以及命中點至事件攻擊者位置不超過12.5公尺；處理事件時仍須持用該武器。RAW描述同樣是 Close Kill；`on_slide` 只是內部 key 名，不是實際觸發。
- Needle Pistol 是自訂 parent：一般近距離遠程擊殺仍可加層，另監聽命中標記與 `on_minion_death`。標記路徑限伺服器、實際針彈手槍 Mk VI/Mk II、遠程命中存活目標且持用副手 slot；毒素關鍵字消失後，標記直到超過一個固定影格寬限才由 update 清除。死亡檢查只要求 server、目標仍在此持有者的標記表、`damage_type=toxin`、死亡位置存在，並且事件 `attacking_unit` 到事件位置不超過12.5公尺；此檢查不要求攻擊者是持有者、不比對 `attacking_item`，也不重查當下毒素關鍵字。死亡管理器把事件送給受害者敵方有效玩家的 buff extension；因此其他攻擊者的毒素死亡事件也可能提出請求，但此 trait parent 的持用副手 gate 仍須通過。其 child_duration 由 own tier覆寫為3秒。
- 每個武器自己的 trait tier 將 `stat_buffs.reload_speed` 和 `child_duration` 寫入 parent tier override；父模板沒有相同的常駐 reload_speed key，因此不會給永久 tier值。ParentProcBuff 建立一個 stack_offset=-1 placeholder，再由合格事件建立/堆疊普通 child buff；child已存在 `stat_buffs.reload_speed` key，同名 tier override取代 child預設+10%，每個有效層才加本級+7/+8/+9/+10%。
- 內部 child max_stacks=5、offset=-1，ParentProcBuff計算6個 physical槽（含 placeholder），對應最多5個有效玩家層。每個通過的事件都重置共享 child_duration 計時器；包括已達 cap、此次請求新增0層的事件。到期後 update 移除最多5個額外層，留下無有效效果的 placeholder。parent 真正銷毀時移除其children。
- held-slot條件限制新事件處理，不會自動加到一般 child 的常駐stat路徑。child由玩家 buff extension持有；切出時條件不讓父層接受該武器的新觸發，但已建立的 child stat仍計入玩家 `reload_speed` cache直到清除。重新計時/統計cache更新後，新開始的任何實際 reload action 才讀到最新stat。
- 23個實際型號模板內共核出29個列有 `buff_stat_buffs.reload_speed` 的 reload action block。一般整段 reload_state、逐發 shell reload與Mk III/Mk VIII特殊彈 `ranged_load_special` 都直接使用 `reload_speed`。Shotgun P3 的 special 是切換，不是裝填；Needle 的 chem cycle 也不是 reload consumer。
- ActionHandler 在每個 action 開始時計算並保存 time_scale/end time，使用當時 weapon handling 與該動作聲明的 stats，再受動作倍率上限夾制。`ActionReloadState`、shell reload與特殊彈補入點都繼續使用已保存 time_scale；開始後取得或失去Speedload不追溯改寫該段。

- `reload_speed` 是 `additive_multiplier`。令 `p` 為每有效層的等級值（0.07／0.08／0.09／0.10），`n` 為有效層數（0–5），`q` 為相同取樣時點的其他裝填速度加成合計。則速度倍率 `M=1+q+n×p`。
- 若同一裝填動作段的 handling、其他條件與 cap狀態相同，基準速度倍率是 `1+q`，加入本項後 `T₁=T₀×(1+q)/(1+q+n×p)`。逐發裝填的每個新動作段分別取樣；不能把一段比例直接當成跨多段 reload chain 的固定總時間縮短。
- q=0且5層時，I／II／III／IV速度加成分別+35%／+40%／+45%／+50%；對應單段時間比例為74.07%／71.43%／68.97%／66.67%。速度增加百分比與時間縮短百分比不同。
