## 執行與計算

兩個 own trait 分別定義四階並綁各自 buff wrapper；wrapper 使用 is_item_slot_wielded。裝備時套用 on_equip buff，條件函式比較 trait item slot 和目前 wielded slot。tier conditional_stat_buffs override 會完整取代 wrapper 預設條件表，不會在 tier 值上再加 wrapper 預設 10°／1 次／0.5。三個 stat key 是 value type，按一般規則累加。

兩種實際連鎖 action 的 helper setup 保存解析後 weapon-chain profile 及 buff extension。每次 make_chain_from_target 先 reset graph，再同步找目標；持用條件進入 stat cache 後，第一個合格新 chain search 即可使用加值，不需先累積層數。每次新搜尋讀一次 buff_extension:stat_buffs() 並計出 max angle、close angle、radius、max jumps 後用該參數走完整跳躍搜尋。Hitscan 在有效命中處理後起鏈；Powermaul 掃擊僅第一個合格命中能起鏈。

切出時 held condition 在之後 stat-cache rebuild 中不提供條件 stat；武器仍在 inventory slot 時 on_equip wrapper 不等於已移除。切回後，在後續 cache evaluation 重新符合。單次 chain search 的 targeting values 不會因 held predicate 改變而回溯重算；後續新 chain search 才讀當時 cache。不能由此推定同一幀切槽／更新次序。兩類 action finish 都呼叫 helper cleanup。wrapper 沒有本項堆疊、期限、冷卻或 proc refresh；實際卸下該武器槽才移除 on_equip buff。

主控補證：步槍命中後沒有存活根時，ActionShootHitScan95–135另讀action_settings.chain_settings作前置尋根；本項兩動作沒有此欄位，故使用default radius4，沒有映射到本祝福radiusstat。隨後ChainLightningAction另讀已解析nativeweaponchainprofile與cache，才套本項加值。不能由helper名稱closest推定真正按最近距離排序；實作先保留一個合資格存活目標，優先已觸電者。

令原生解析後最大角、近距最大角、半徑、最大跳躍參數為 A、C、R、J，祝福加值為 Δθ、ΔR、ΔJ。搜尋使用 A+Δθ、C+Δθ、R+ΔR、J+ΔJ；profile 未給 close angle 時 C=A。原生角度／半徑部分以 lerp endpoints 表達，依解析 profile 而定；jump base 可直接精算。此效果不在傷害乘式內；鏈結傷害 profile/type 由 action/weapon chain_damage_settings 分開指定。angle formatter 先 radians_to_degrees 再 math.floor，display +7/+12 和 runtime +7.5°/+12.5°分開。
