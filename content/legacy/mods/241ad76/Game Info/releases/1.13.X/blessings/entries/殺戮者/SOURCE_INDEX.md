## 執行與計算

七個實際武器族各自的完整 I–IV 定義都覆寫 `power_level_modifier` 為 .05／.06／.07／.08；每個 own wrapper 先複製 `increase_power_on_kill_parent`，將 child 名稱改成該族專屬 ID，再複製 `increase_power_on_kill_child`。逐檔搜尋均只有上述 parent、child 名稱三處，沒有同 ID 的後置覆寫。父層引用同名 child，持續 4.5 秒、`stacks_to_remove=5`，監聽 `on_kill`；檢查函式要求相同 attacking item，且 attack result 為 `died`、attack type 為 `melee`。這裡沒有距離、弱點或特定敵種條件。

每個有效擊殺事件增加一個子層，父層允許已啟動時再次處理事件，沒有另設冷卻。child 的 `max_stacks=5`、`stack_offset=-1`；父層建立時先生成一個佔位 child，因此實體容量為六，起始有效層數為零，最多五個有效層。child 的 `.2` conditional fallback 與 own tier 的同名 `stat_buffs.power_level_modifier` 由 Buff 對同 key 覆寫機制選取：只加 tier 的 .05／.06／.07／.08 每層，不會另加 .2。

父層與 child 都檢查是否仍持用綁定物品。離手會停用觸發與威力修正，但父層 4.5 秒共用計時繼續走；切回且未到期時，剩餘層數可在條件與屬性更新後恢復。每次合格事件都呼叫同一加層程序並重設共用期限；達五層時雖無新 child 加入，期限仍刷新。到期判斷使用 `remove_t < t`，而 `stacks_to_remove=5` 足以一次移除最多五層。父層真正被移除時，destroy 會移除外部管理的所有 child。

每次獨立 `Attack.execute` 在傷害結果確定為死亡後才送出 `on_kill`。近戰揮掃會以相同攻擊物品、`attack_type=melee`逐目標呼叫 Attack；因此一次揮掃若殺死多個目標，可按各自接受的擊殺事件增加層數。鏈斧黏附追加實例沿同一 ActionSweep attack type/item 傳入；只有追加實例另行造成死亡時才有額外合格事件。推擊 helper 明確傳 `attack_type=push`，不符合 melee predicate。Force Sword P1 的 `action_fling_target` 用 `damage_target` 執行並傳 `attack_type=ranged`，即使擊殺也不符合。其他武器特殊啟動動作本身不造成攻擊；其後若以 sweep 命中並擊殺，仍按一般近戰路徑處理。

觸發條件不代表所有受益攻擊的限制。child 增加未限定攻擊類型的 power_level_modifier；持用條件成立、屬性快取已有該值時，ranged 的 Force Sword fling、push 的衝擊與 Powermaul 額外 explosion 都可讀取通用威力。但甩飛各護甲生命傷害倍率皆0，純推擊 attack power 為0，兩者僅可能在 impact/stagger 路徑受益；盾牌 extension 用 profile 的固定 shield_override_stagger_strength 時會覆寫計算值。Powermaul 特殊類別的額外爆炸使用同一 item、attack_type=explosion，不符合 melee on_kill；Thunderhammer 的 gibbing_type=explosion 只是 profile 標記，實際配置的 WeaponSpecialSelfDisorientation 不產生額外爆炸 Attack。直接近戰事件新增層後仍須等待屬性更新，不能推定同一次動作的後續爆炸已讀到新值。

令 `p` 是 I–IV 每層的 `.05/.06/.07/.08`，`n` 是有效層數（0–5），`q` 是該次攻擊條件下其他合計威力修正，`B` 是威力類型曲線已換算、尚未套用威力修正的輸入。`PowerLevel` 先算威力類型曲線，再乘合併修正，因此本祝福使威力輸入為 `P = B × (1 + q + n×p)`。此結果會進入後續攻擊/衝擊等計算；不直接決定固定比例的最終生命傷害。
