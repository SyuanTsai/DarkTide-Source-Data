## 執行與計算

四個實作各自覆寫父層 `max_stacks=5` 與子層 `conditional_stat_buffs.power_level_modifier`，I–IV 分別為 0.0425、0.045、0.0475、0.05；四個父／子 buff wrapper 都接到共用的 `stacking_power_bonus_on_staggering_enemies_parent`／`child` 基礎並保留自身子層名稱。基礎父層只處理 `on_hit`，同時要求 `on_item_match` 與 `on_staggering_hit`，並以 `is_item_slot_wielded` 作為 `conditional_proc_func`。共用 ProcBuff 將同一條件用於事件接收及其 stat/keyword 貢獻，因此目前持用是觸發與生效的共同門檻。

`on_item_match` 比較 `attacking_item.name` 和祝福 buff 的 `template_context.item.name`；`on_staggering_hit` 以 Attack 計算出的 `stagger_result` 為準，只接受已套用踉蹌。它不另看近戰／遠程類型，也不看是否擊殺。唯一額外通過支線是明確啟用 `adamant_melee_weakspots_count_as_staggered` 時，近戰弱點命中可按踉蹌處理。

Attack 先計算傷害，再執行 HitReaction 並把結果放入 `on_hit` 事件；ProcBuff 在後續事件處理中驗證條件。每個合格 on_hit 加一個子層。子層 `max_stacks=5`、`stack_offset=-1`，父層實際容量為五個有效層加一個不加值的佔位層。2.5 秒沒有合格刷新後，父層移除最多五層；達上限時的合格事件雖不增加層數，仍會更新父層期限。

子層的通用威力修正亦受目前持用的條件控制。切換武器不等於刪除已裝備來源 buff，因此計時可在切槽期間繼續；真正卸下祝福物品則由來源 buff 生命週期移除父層與子層。

Bolter 的 hitscan route 另會依 fire_configuration 將原物品交給 HitScan。Mk IIb 的 `default_bolter_boltshell` 基礎引爆距離為 5，Mk III 的 `bolter_m2_boltshell` 為 3；達距離後，命中消耗 hit-mass 時按 kill／stop 結果選爆炸，穿透停止也可走 stop explosion。爆炸逐目標呼叫 `Attack.execute`，帶 `attack_type=explosion` 與原始 Bolter item；四個實際 kill／stop profile 都有 stagger category、沒有 `skip_on_hit_proc` 覆寫，所以目標攻擊會依一般 `on_hit` 路徑送出其實際 stagger_result。Pinning Fire 不檢查 attack_type，仍只在該目標實際被踉蹌、事件來源物品相符且當下持用時加層。這些爆炸模板的 Power 為 static 500；該值在建爆炸時選定，而 generic `power_level_modifier` 由每個目標 `Attack.execute` 的威力計算透過當時的 attacker stat cache 取用，不能假設爆炸建立時已固定該祝福修正。

本項修改的是通用 `power_level_modifier`。在其他威力修正合計為 `q`、有效層數 `k`、每層係數 `p`，且原生 Power 曲線輸出為 `P_curve` 時，受控表示為 `P_after = P_curve × (1 + q + k × p)`。其中 `p` 依等級 I–IV 為 0.0425／0.045／0.0475／0.05，`k` 最多為 5；實際程式先完成威力類型曲線，再套用合併後的威力修正。後續傷害仍須經該攻擊的 profile 與目標防護計算。
