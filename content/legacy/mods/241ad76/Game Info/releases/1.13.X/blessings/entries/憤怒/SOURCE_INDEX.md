## 執行與計算

- 十個武器變體的 wrapper 都只 clone 共用 parent/child，並把 parent.child_buff_template 指向本武器 child，沒有額外同前綴 gate。共用 parent 對 on_sweep_finish 設 100% proc；active_proc_func 僅在 num_hit_units > 0 成立。成功事件最多為該次掃擊增加一層，不按該次命中的敵人數增加。Parent 建立時先加一個 child stack 作隱藏基準；child max_stacks=5 且 stack_offset=-1，所以內部總數最多6、有效數為 clamp(raw−1,0,5)。成功掃擊會呼叫 child-stack helper；即使已達上限、實際新增數為0，helper仍在零次迴圈後重設 parent 的 child_duration 起點；漏擊時 active 變 false，移除除基準層外全部 child stack。若3.5秒未再加層，server update 在 remove_t < t 時按 stacks_to_remove=5 一次清掉所有有效層；固定更新可能略延後。reset_update_func 回傳 false，所以沒有額外週期重置。Parent 與 child 的 proc/stat 都檢查相同 item slot 是否正持用；切換時加成不作用，來源沒有專屬切換清層事件。Trait 的 tier stat override 由 parent_buff_template 傳給 child，經 child 的 conditional_stat_buffs 套用至 max_hit_mass_attack_modifier。

- 滿層時仍呼叫 `_add_child_buff_stack(t,0)`；零次添加迴圈結束後，helper仍重設3.5秒移除計時。不能把「零新增」誤當成「不刷新」。

- on_sweep_finish只由ActionSweep產生；事件不帶attacking_item檢查，也不檢damage/crit/weakspot，parent只驗持用槽位和num_hit_units。ActionSweep只將命中前存活的character計入hit_enemies，命中後是否死亡不改這個已計入的命中。

- Sticky開始先設is_sticky，普通damage-window出口不發sweepfinish；每次鋸傷只執行Attack.execute與buff_to_add_tick，不送該事件。停止黏附時helper646–664發一次；finish捕捉原sticky狀態避免重複普通出口。

- Push只送on_push_finish；activate/toggle/overload特殊動作只設定active flag，不發sweepfinish。

- 設 c 為該武器、該等級每層加成小數（例如35%=0.35），raw 為共享 child buff 的內部 stack_count。有效層數 n = clamp(raw−1,0,5)。本祝福提供的 additive multiplier 增量為 B=c×n；只考慮本祝福時，max_hit_mass_attack 最終倍率=1+B。若有其他攻擊順劈修正，damage_profile.lua 會把相應 modifier 相加後再乘上基礎 max_hit_mass_attack。這個值調整可穿透的攻擊質量，不是線性目標數公式，也不改 max_hit_mass_impact。

- 同一順劈additive group每層增量相加；一般IV五層+2，另+0.2時基礎倍率3.2。動力劍IV五層3.5倍；骨鋸IV五層2.25倍。

- 父層數raw上限6、offset−1；有效n0–5。child override取parent trait tier，替換模板預設0.5，不再另外加0.5。

- 持用槽位不符時proc/stat停用但timeout仍更新；沒有reset_update清層分支，因callback回傳false。
