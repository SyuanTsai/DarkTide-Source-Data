## 執行與計算

## 本項固定資料

盤點確認 6 個實作、14 個實際型號 binding，全部為遠程武器；等級 I–IV 的 `active_duration` 依序為 2.4、2.8、3.2、3.6 秒。六個武器 wrapper 各自 clone 同一個 `suppression_negation_on_weakspot` parent，沒有本項後續覆寫。

## 命中、清除與快取

Base parent 的 `on_hit` 條件要求目前持用槽位符合 wrapper、命中事件的 `attacking_item` 與 buff context item 相同，且 `hit_weakspot` 為 true；它沒有 attack-type 條件。事件處理後會呼叫 `Suppression.clear_suppression(owner)` 並啟動單一計時窗。實際 `on_hit` 是否發出仍受攻擊傷害檔案的 `skip_on_hit_proc` 等事件／profile 閘門控制。

Buff 固定更新先處理 buff，再送入 proc events，最後更新 keyword cache。故首次合格命中先按自身攻擊路徑結算，之後才清除壓制並使 `suppression_immune` 在新的快取中生效。壓制免疫期間，suppression extension 在累積壓制前檢查該 keyword；proc 本身也清除已累積的 suppression 相關狀態。

## 各路徑適用界線

14 個實際 Mark 的腰射與瞄準射擊使用 hit-scan，透過實際命中區域產生 `hit_weakspot`。槍托掃擊和手槍推擊則是不同 Attack 路徑；由於 parent 沒有 attack-type gate，它們只有在實際 `on_hit` 帶 `hit_weakspot=true`、同一來源武器且 profile 沒有略過事件時才符合。Needle direct／AoE 結果同樣不能只看攻擊名稱推定符合；cycle-chem、flashlight 與 brace reload 等切換／裝填動作本身不會產生弱點命中。

## 持續時間

`T = active_duration(等級)`：I=2.4 秒、II=2.8 秒、III=3.2 秒、IV=3.6 秒。每次合格事件處理時重設 `active_start_time`，有效條件為 `now < active_start_time + T`；沒有層數乘法，也沒有額外冷卻。

## 效果順序

攻擊命中先完成自己的傷害／命中路徑；合格 `on_hit` 事件稍後清除壓制並刷新期限。`player_unit_buff_extension` 固定更新先處理 buff，再處理 proc events，最後重建關鍵字快取，因此新免疫不追溯本次命中，從更新後可讀取的 `suppression_immune` cache 起生效。
