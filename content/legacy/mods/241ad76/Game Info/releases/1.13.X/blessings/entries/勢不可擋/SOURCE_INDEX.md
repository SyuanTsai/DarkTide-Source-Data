## 執行與計算

三個實際武器 wrapper 都直接建立 ProcBuff，tier 覆寫 `melee_fully_charged_damage`。Buff 計算先把 tier 同 key 的普通 stat 覆寫套用到 wrapper 基礎值；同一 key 的 tier 值取代基礎 2.5%，不是再疊一份。普通 stat 與常數關鍵字不以 held/active 條件 gate。裝備武器把 on_equip Buff 加到玩家 BuffExtension；切槽只改 on_wield 類 Buff，卸下武器才移除 on_equip Buff。

`fully_charged_attacks_infinite_cleave` 是常數關鍵字；自動完成掃掠的貫穿消費端將最大 hit mass 設為無限。`melee_fully_charged_damage` 消費端則同時要求自動完成、近戰攻擊、profile 為重型。這兩個消費端讀玩家的共用 stat／keyword 快取，不比較 attack item。

另一個條件關鍵字 `ignore_armor_aborts_attack` 只在 `template_data.active` 且祝福物品正手持時加入。wrapper 的 sweep-start 回呼只在 profile 重型且物品手持時設 `active=true`；sweep-finish 回呼設回 false。`ActionSweep` 在開始時排入帶 `is_heavy`、`is_auto_completed` 的事件，PlayerUnitBuffExtension 隨後先處理 proc event，再重建 stat/keyword 快取，故不能保證同幀立即生效。

裝甲關鍵字只繞過 `Armor.aborts_attack` 分支；breed 中止另行判定。正常進入傷害視窗並完成／中止的掃掠會送出 Buff 的結束事件。若某個實際重型掃掠在傷害視窗前結束，ActionSweep.finish 該分支不會送出此 Buff 結束事件；實際 M2 Mk III 直接推擊追擊路徑有格擋鏈，且傷害視窗始於 0.3 秒。只有在開始事件已處理、格擋於傷害視窗前結束、又無其他結束事件的條件下，active 才可能殘留。held gate 在切槽時隱藏條件關鍵字，並不重設 active；卸下祝福武器會移除 Buff。

Crowbar 特殊重擊可走 sticky 額外傷害路徑；該額外 `Attack.execute` 沒有傳入自動完成旗標，故它不另行取得完全蓄力傷害增量或貫穿關鍵字。特殊模式啟用／切換自身不會觸發祝福。

令 `d` 為 tier 覆寫的 `melee_fully_charged_damage`，`B` 為符合條件攻擊在本祝福增量前的傷害計算值。I–IV 的 `d` 依序為 `0.025`、`0.05`、`0.075`、`0.10`；本項直接增量為 `B × d`。只有 auto-completed、近戰且 profile 為 heavy 的攻擊才把此 stat 加入傷害計算。這是傷害增量，不是百分點、命中數加成或不受其他乘數影響的最終傷害。

靜態 UI formatter 將這四個比例格式化為 +2.5%、+5%、+7.5%、+10%；RAW 使用 `{damage:%s}` 占位符。貫穿效果是獨立的常數關鍵字，不應換算成傷害百分比。裝甲例外是第三個獨立的條件關鍵字，也不改變 damage stat 或最大 hit mass。
