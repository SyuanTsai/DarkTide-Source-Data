- 八個 own tier 都覆寫 `stagger_count_damage=.14/.16/.18/.20`；八個 wrapper 都直接 clone base `stagger_count_bonus_damage`。Base held-slot conditional fallback `.5` 由 own tier 同 key 取代，不會另加 `.5`。本項沒有自己的 proc、層數或期限。
- `Attack.execute` 在傷害前讀目標 `stagger.count`（缺 component 時為 0），傳給 `DamageCalculation.calculate`。`_calculate_damage_buff` 將 `(stagger_count_damage−1)×clamp(count,0,7)` 加進 `damage_stat_buffs`，而 `stagger_count_damage` 的中性聚合值為 1。
- `_base_damage` 先取得 `_power_level_scaled_damage` 的 `base_damage`，再以 `damage_stat_buffs` 計算額外 `buff_damage`；本項改變此通用計算的乘算池，不是生命值傷害門檻或獨立 HP 傷害。零基礎傷害的純盾推不會因此得到生命值傷害。
- 傷害先算，之後才套用 `HitReaction`。所以本次傷害不能追溯使用本擊新產生的踉蹌計數；後續分開結算的攻擊可以使用更新後 count。這個元件 count 與 `num_triggered_staggers`／`count_as_staggered` 不同。
- 列出的直接射擊、pellet、蓄力鐳射、電弧鏈及有傷害的近戰槍托／刺刀／斬擊都經通用 DamageCalculation，持用時可讀該 stat。Mk IX 燃燒狀態另以 owner/source item 在後續 tick 呼叫 Attack。
- 被動 buff on_equip 隨武器安裝；held-slot gate 控制 conditional stat。切槽由條件快取停用／恢復，真正卸下裝備才移除來源 buff。

令 `B` 為 `_base_damage` 中 `_power_level_scaled_damage` 輸出的 `base_damage`，`p` 為 tier `.14/.16/.18/.20`，`n` 為本次 DamageCalculation 開始時目標的原生 `stagger.count`。本項加入 `damage_stat_buffs` 加算池的項目為 `a=p×clamp(n,0,7)`；若既有同池加算為 `q`，且 `damage_taken_stat_buffs=1`、`buff_damage_bonus=0`，`_base_damage` 的中間輸出為 `B + B×(q+a) = B×(1+q+a)`。因此 `B=100, p=.20, n=4, q=0` 時係數 1→1.8、輸出 100→180；係數增加 80 個百分點，該受控輸出相對增加 80%。`B` 是已通過該武器／攻擊基礎曲線的輸入；後續護甲、命中區及傷害階段仍會改變最終生命值扣減。
