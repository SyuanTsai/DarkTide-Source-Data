## 執行與計算

- 實際兩個 trait item 分別限制於 thumper_p1、thumper_p3 category，並由各自 weapon template 匯入 bespoke trait module；實際 Marks 為 ogryn_thumper_p1_m1、ogryn_thumper_p1_m3，P3 category 不能推成 Mark p3_m1。
- 兩個 wrapper 都是 on_equip 安裝的 ProcBuff，收到 on_shoot 後以 check_item_slot 與 on_shoot_hit_multiple 的 all 條件檢查；命中門檻為3、max_stacks=1、無 cooldown，fallback duration=4秒、base melee_power_level_modifier=.05、predicted=false。I–IV 將 duration 覆寫為3.5秒，修正覆寫為.30/.34/.38/.42。
- slot 檢查先比對事件的 item_slot_origin；沒有該欄位時檢查 projectile origin slot；兩者皆無才回退目前 wielded slot。P1/P3 原生 on_shoot 事件不填前兩個欄位，故走目前持用槽 fallback。這是觸發當下的檢查，不是持續 held gate。
- P1 在一發射擊處理完成後，依直接受擊 unit map 的不同單位數送出 on_shoot；多顆 pellet 命中同一單位仍計一次。P3 實際使用 shoot_hit_scan，HitScan 對可結算的直接命中單位計數後送 on_shoot；武器卡片的 projectile 標籤不改變 runtime hitscan 路徑。兩種實際 impact template 都沒有配置額外 explosion template，爆炸旁傷不會另加至此 hit counter。
- 兩個實際型號的 Bash／右側 Bash 都是 melee sweep，呼叫 Attack.execute 而非 on_shoot；掃中多人不會走本祝福的觸發事件。兩個型號沒有本祝福接入的 push、throw、charge 或 delayed projectile route。
- 合格 ProcBuff 在事件處理時間更新 active_start_time；有效條件為 t < start+duration。可在有效期間重新觸發，max_stacks=1 只刷新起始時間、不新增層數。Player fixed update 先處理 proc queue，再更新 stat cache；觸發的那一發已完成傷害，後續近戰才讀到新值。切換武器槽不移除仍裝備物品提供的 on_equip Buff；從裝備槽卸下才移除。
- melee_power_level_modifier 僅進入 attack_type=melee 的 power-level 計算。本級增加比例作用於近戰 power-level 輸入，不等於近戰最終傷害固定同率增加；profile、目標、距離、護甲、部位及其他傷害修正仍參與結算。

令δ為當級 own melee_power_level_modifier（I–IV=.30/.34/.38/.42）。PowerLevel.power_level_buff_modifier 僅在 attack_type=melee 納入該修正，和其他倍率以中性1為基線組合；假設其他項不變且中性，P_melee' = P_scaled×(1+δ)。IV級 P=100 時為100×1.42=142。這不是最終傷害倍率；DamageCalculation 還使用武器 profile、目標、距離、護甲、weakspot/finesse、hitzone及其他修正。
