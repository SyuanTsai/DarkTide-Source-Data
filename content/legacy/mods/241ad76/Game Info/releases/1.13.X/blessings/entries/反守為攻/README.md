# 反守為攻(Offensive Defence)

[祝福目錄](../../README.md)｜[來源與公式](SOURCE_INDEX.md)

<img src="https://github.com/user-attachments/assets/fade3668-fc4f-47f8-8a9d-8bc9748930f7" width="72" height="72" alt="反守為攻祝福圖示">

- **觸發方式**：裝備並持用板盾或鎮壓護盾，格擋目前動作能接住的來襲攻擊時會累積該次格擋消耗。這項效果不要求格擋把耐力條打空。 累積消耗以下記為 `T`。格擋與掃掠事件依處理時是否持用本武器欄位判定，不另外比對事件來源武器。
- 新層不是回溯效果：格擋後要等遊戲處理這次格擋並更新威力快取，之後開始計算的近戰攻擊才會用到；格擋發生前已算好的攻擊不會被補算。
- 每層會提高近戰攻擊威力：I–IV 為 +4／+6／+8／+10%，最多五層。這加在攻擊威力計算中，不能直接當成相同百分比的最終生命傷害。
- 格擋消耗會依公式換成有效層數：單次消耗值為1時會得到2層；兩次各0.6、且間隔未超過3.5秒時會累積成2層。原文「每消耗一點耐力一層」無法精確描述這個結果，而且格擋消耗值不一定等於耐力條實際扣除量。
- 每次完成一段近戰掃掠最多扣一層，不按命中敵人數扣層。掃掠已進入攻擊判定階段後，即使揮空也會扣；在該階段開始前取消則不會。四個型號的輕擊、重擊和推擊後追擊都屬掃掠；單獨推擊不是。一般 ActionPush 也會保留來襲格擋窗口：板盾 M1／M2 為0.5秒，鎮壓護盾 M1／M2 為0.4秒；推擊本身不觸發掃掠完成或增加 T，但窗口內若成功格擋可接住的來襲攻擊，仍會觸發 on_block。
- 格擋與掃掠完成共用3.5秒計時窗，兩種事件都會重新計時。逾時後有效層清空；之後的格擋通常從當次消耗重新計算。若逾時後先處理一段掃掠，保留的計數會被改寫並重新計時；其後的零消耗格擋雖不增加消耗，仍可能依該計數重算有效層。這是依特定事件先後得出的邊界情況，不代表零消耗格擋通常會加層。
- 板盾 M1／M2 的武器特殊是零成本格擋，特殊期間接住攻擊時不增加累積消耗。鎮壓護盾 Mk VI／Mk XI 的放出動作開始時即保留0.4秒格擋窗口；推吼設定在該動作開始後0.25秒發出，因此與窗口重疊。窗口內若格擋到攻擊，仍按一般格擋規則累積。推吼是獨立攻擊，不是格擋或近戰掃掠：不讀本祝福的近戰威力修正，也不消耗掃掠層。
- 切換武器不會卸下來源祝福，3.5秒計時仍會走；離手期間不會處理新的來源事件，近戰威力效果也暫停，切回且層尚未逾時後再生效。真正從裝備欄卸下來源武器才會移除祝福狀態。

## 計算與算例

- **前提（兩層示例，k=2）**：中性其他修正；每次實際格擋事件送入 `block_cost=0.6`，兩事件間隔小於3.5秒，來源盾錘一直手持。
- **代入**：第一次後 `T=0.6`、`k=1`；第二次後 `T=1.2`、`k=2`。完成一次推擊追擊掃掠後，`T=0.2`、`k=1`。
- **結果**：在IV、`k=2`時，每層+0.10，故威力池倍率是 `1+2×0.10=1.20`。
- **玩家意義**：這是由實際事件數字和掃掠完成事件推算出的威力階段倍率；攻擊曲線、護甲、其他修正及後續傷害結算仍會影響生命傷害。

- **前提**：示範一個有效的格擋事件，其 `block_cost=1`，當前 `T=0`，不考慮其他層來源。
- **代入**：`floor(1)+(1>0?1:0)=2`，因此有效層數變成2。
- **結果**：I/II/III/IV 對此兩層分別為 +8／+12／+16／+20% PowerLevel 修正。
- **玩家意義**：原文「每消耗一點耐力一層」不能精確描述這個公式；`block_cost` 也不一定等於耐力條實際減少量。

## 遊戲描述勘誤

英文與繁中 RAW 都寫每消耗一點耐力格擋獲得一層；實作把 `on_block` 的 `params.block_cost` 加入 `T`，再計算 `k=clamp(floor(T)+(T>0?1:0),0,5)`。在 `T=0` 且一次事件 `block_cost=1` 時會產生2個有效層，而不是1層；此外 `Stamina.drain` 可能另乘成本修正並截斷剩餘耐力，本項仍讀原始 `block_cost`。這是數量／輸入差異；靜態 +4/+6/+8/+10% formatter、3.5秒及5層上限本身相符。
