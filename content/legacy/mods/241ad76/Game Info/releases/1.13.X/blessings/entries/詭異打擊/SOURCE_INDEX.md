## 執行與計算

- 五個實際 wrapper 都 clone `targets_receive_rending_debuff_on_weakspot_hit`；本體只用 own `target_buff_data.num_stacks_on_proc` 覆寫每次事件加層數，沒有 attacker-side rending 欄位。
- 共用 parent 的 `check_proc_func` 是 `all(on_item_match, attacked_unit_is_minion, on_weakspot_hit)`，另有持用條件；沒有 attack_type gate。`Attack.execute` 從 hit-zone 算出 `hit_weakspot`，而其一般 on_hit 事件會附上 `attacking_item`、`attacked_unit`、`attack_type` 及 `hit_weakspot`。
- `add_debuff_on_hit_start` 從 own tier 讀 `num_stacks_on_proc`；callback 若目標已非 HEALTH_ALIVE 或沒有 buff extension 就不加。helper 以 parent `max_stacks=31` 計算請求追加量；目標端 standalone `rending_debuff` 的實際 `max_stacks_cap=16` 再限制有效層數。期限刷新由同名目標 buff 的 stack/add 路徑處理，包含已達16層時的刷新。

- 烈焰力場劍 朦朧 Mk II、戴莫斯 Mk IV 的模板將輕／重掃掠接到 `light_sticky`／`heavy_sticky`。只有動作開始時特殊狀態已生效、掃掠被合格碰撞中止，且目標部位／護甲允許時才進入黏附。設定各安排 3 個 damage instances；`ActionSweep._update_hit_stickyness` 逐段以黏附 actor 的 hit-zone、玩家、同一武器 item、`attack_type=melee` 呼叫 `Attack.execute`，最後一段另用 `*_sticky_last` profile，並配置 `sticky_dodge_push`。這些 Force Sword profile 設 `sticky_attack=true`，但家族 profile 檔沒有 `skip_on_hit_proc`；一般 on-hit 路徑仍會檢查每段的 `hit_weakspot`，所以只有各段本身通過來源物品、Minion、存活與弱點條件才加層。既有 action coverage 與實際 Mark 設定列出哪些輕／重掃掠可走此路；伊利斯 Mk V 使用 active-cleave profile，沒有同一黏附設定。若黏附因進入閃避而結束，ActionSweep 在目標與 actor 仍可用且非重演時，另以 sticky_dodge_push、actor 當前 hit-zone、同一武器 item 和 melee attack_type 呼叫一次 Attack.execute；該退出命中也走一般弱點／目標條件，並非三個排程 instance 之一。事件後新層不追溯已結算的那一段。
- Minion 的 standalone `rending_debuff` 以 `rending_multiplier=.025`、5 秒、cap 16 實際建立在目標端。Buff extension 依同 template name 管理 stacking instance；stack 增加時依 refresh flag 重設起始時間，達到 16 層時由目標端 max_stacks_cap 接受檢查刷新期限；這與來源 helper 的 31 層請求界限分開。
- DamageCalculation 把 target rending 放入 17 項 additive rending pool，總 rending clamp at 1，接著依實際 armor/profile 結算；不是將 +2.5% 直接乘到全部最終傷害。
- 共用事件／裝備機制只在此五個 wrapper 確實 clone 上述 base、傳入符合的 own item、事件帶弱點旗標與 Minion target 時適用；詳見固定來源及 source blocks。

令 `n` 為本次合格事件追加層數，`s` 為目標當前層數：`s_after = min(16, s + n)`。每層目標 rending 加算量 `r = 0.025`，故 `R_target = 0.025 × s_after`，上限為 `0.40`。一般四系 `n=(2,4,6,8)`，短刀雙刃 `n=(1,2,3,4)`。期限是目標 debuff 的 5 秒，接受新層或已滿層觸發刷新；它不是攻擊者 buff 的個人疊層。

Rending 再與其餘攻擊者／目標 rending 項相加形成 pool，總值上限 1；該值按傷害 profile 與目標護甲進入 armor damage calculation，後續還可計算 finesse 及其他修正。因此層數、rending pool 百分點與最終 HP damage 必須分開描述。
