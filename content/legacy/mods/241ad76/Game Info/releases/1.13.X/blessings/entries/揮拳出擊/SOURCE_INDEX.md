## 執行與計算

三個實際 trait wrapper 都是非預測 `ProcBuff`，各自監聽 `on_push_finish`，允許效果存續中再次觸發，並以 `is_item_slot_wielded` 作條件。`check_proc_func` 只檢查 payload 的 `num_hit_units > 0`；沒有 same-item、弱點、暴擊、擊殺或目標種類檢查。逐級 `proc_stat_buffs.weakspot_damage` 覆寫基礎 wrapper 的同名 fallback，持續時間則由每個 trait 的 tier override 決定。

實際的 `ActionPush.fixed_update` 到達 `damage_time` 才呼叫一次 `_push`。`PushAttack.push` 對 overlap actor 去重，略過 death-manager-owned 單位，再按 push 力量、方向角度及 inner／outer profile 選擇逐目標 `Attack.execute`；只有取得 profile 的目標會計入命中數，計數在呼叫後增加，不檢查 damage_dealt 或擊殺。Attack 使用 `attack_type=push` 及 `hit_zone_name="torso"`。之後 ActionPush 只發出一次 `on_push_finish`，並以整次推擊的計數填入 `num_hit_units`；零命中事件被 trait check 拒絕。

合格事件更新 `ProcBuff.active_start_time`；再次觸發時起點重設，沒有子層或堆疊。`active_duration` 依 `t < start + duration` 判斷。`is_item_slot_wielded` 也控制 stat 是否進入目前屬性快取，因此切槽期間計時仍走、加成暫停；卸下物品才移除 on_equip trait buff。

`weakspot_damage` 是通用 stat。傷害計算只在 `hit_weakspot` 分支將它加進弱點 damage modifier，並與其它 finesse 修正共同乘 `base_finesse_damage`；普通／重擊／推擊後 Sweep 命中弱點時可讀取，但推擊觸發本身不保證弱點命中，也不會因推擊計數直接增加傷害。

令 `p` 為本祝福該級的 weakspot_damage 增量，`M₀` 為沒有本祝福時、已合併其他弱點與 finesse 修正的係數，`F₀` 為該 profile 的基礎弱點 finesse 傷害分量；在同一目標／profile 前提下，弱點 finesse 分量為 `F = F₀ × (M₀ + p)`。當其他修正皆中性時 `M₀=1`，故本祝福單獨增加 `F₀ × p`。總攻擊傷害仍包含非 finesse 部分及目標／profile 修正，不能把 `p` 當作總傷害百分比。

| 等級 | p：弱點傷害 stat 增量 | 中性其他修正時弱點 finesse 係數 |
|---|---:|---:|
| I | +45% | 1.45× |
| II | +50% | 1.50× |
| III | +55% | 1.55× |
| IV | +60% | 1.60× |

例：撬棍 科技教士 型號6 的 `light_crowbar_tank` 是實際推擊追擊 profile；若將此 profile 對所選弱點目標的未加本祝福基礎 finesse 部分正規化為 100、且 `M₀=1`，IV 級算得 `100×(1+0.60)=160`。這只隔離本 stat 的弱點 finesse 分量；該 profile 的攻擊 power、護甲係數、其它修正及總生命值傷害需另按實際目標計算。
